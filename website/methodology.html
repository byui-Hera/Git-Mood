A GUIDE TO YOUR REPORT

How Git-Mood
works.

In Git, a commit is a saved set of changes. Git-Mood looks at these saves and turns them into a few simple numbers. Here is how it counts them.

01 / MAYBE A FIX

Read the message

Git-Mood marks a save as a possible fix if its message has words like “fix,” “bug,” “oops,” or “error.” This is only a guess. It does not check the code for bugs.

02 / CHANGED AGAIN SOON

Look for the same file

Git-Mood checks if a later save changed the same file within 24 hours. This can be normal work. It does not always mean something was wrong.

03 / FILES CHANGED OFTEN

Find files changed most often

The dashboard lists up to eight files that appear in the most saved changes. A file may change often because you are working on it a lot. This count does not tell us if the file is good or bad.

04 / WHEN CHANGES HAPPEN

Group saved changes by time

Git-Mood uses the date and time saved with each commit. Your most active hour is the hour with the most changes. It may not be your most productive hour.

Use these numbers as clues

Git history cannot tell how long you worked, how hard a task was, or how you felt. Look for patterns, then think about what was happening when you made those changes. Git-Mood reads your history on your computer; it does not upload your project files.
